# Backend development tests

`test-launch-plan.mjs` contains pure synthetic planning/CLI/schema tests, not native launch tests.
The only subprocess is the Node planner entrypoint. No Velociraptor binary,
signature/key/cache, helper compilation, token, Job, module, DLL, handle,
reparse, machine collection, network, elevation, or Windows setting is used.

Plans generated by the suite are FullContractInstance launch-plan fixtures,
not valid launch authorities or complete audit graphs. Targeted mutations are
negative inputs. The historical public binary pin and argument arrays are
compared to the retained compatibility records, not to any installed binary.
No raw output or machine evidence is saved.

Run `npm run test:backend-plan`; the suite also runs as part of `npm test`.
It checks deterministic digests, schema validity, exact blocker IDs, immutable
registries, lowering-only limits, command/pin substitution, forbidden override
inputs, getter/proxy rejection, controlled CLI exits, and no request-value
disclosure on argument errors. Passing this suite says nothing about native
Windows containment or production launcher readiness.

`test-native-result.mjs` checks the separately recorded native-synthetic result,
source hashes, exact case IDs and targeted negative record mutations. These
28 tests run through `npm run test:backend-native-result` and `npm test`; they
do not compile or execute native code. The native experiment itself is manual,
requires separate authorization, and is described in
[native-synthetic/README.md](native-synthetic/README.md). Its effective-rights
observations do not close the linked-token or other production launch gates.
